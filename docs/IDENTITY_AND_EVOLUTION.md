# StoryProduction — 정체성과 발전 방향

## 완성할 작업

사용자가 쓴 원문에서 시작해 그 사람의 표현 습관과 이야기 의도를 유지하면서 스토리, 시놉시스, 씬 설계, 대본, 텍스트 스토리보드를 완성한다. 완료의 단위는 프롬프트·모델 응답·영상 작업 접수가 아니라 열고 고칠 수 있는 제작 문서다.

주 사용자는 원작자와 함께 쓰는 에이전트다. 원작자는 핵심 선택과 채택을 결정하고, 에이전트는 자료에 근거한 초안을 작성하고 선택 영역을 고친다. 직접 편집과 에이전트 제출은 같은 소유자의 공개 업무 API를 거친다.

## 소유권

geultu는 원문·집필 브리프·글투·스토리·시놉시스·후보·채택 이력을 가진다. NarrativeCourier STS는 인물 상태·서사 인과·트리트먼트·씬·대본의 권위 모델을 유지한다. NVC 텍스트 콘티는 확정된 씬을 참조하는 연출 문서이며 새로운 서사 정본이 아니다. integration은 파일 참조·공개 CLI 연결·작성 프로세스 실행 기록·불변 내보내기만 맡는다.

SceneMotionCompiler, SceneAssetCompiler, ImagePromptCompiler는 독립된 선택 확장이다. 텍스트 집필은 이미지·영상·렌더링 단계를 요구하지 않는다. 현재 선택 animatic 경로는 NVC 연출 검토·SAC PNG 자산 검토·SMC 합성으로 HTML/VTT/VP9 WebM 후보를 만든다. 후보의 최종 작품 release는 별도다. 제품 화면 제작과 VisualScreenCompiler는 범위 밖이다.

## 품질의 방향

- 작가의 결말·관계·인물 지식·생략·리듬을 명시된 자료와 집필 지시로 보존한다.
- 문체는 원문, 명시적 voice_notes, 기존의 제한된 글투 관찰을 함께 참고한다. 문장 길이의 유사성이나 모델 자기 평가는 작가성을 증명하지 않는다.
- 전체 재생성 대신 선택한 블록/씬의 후보를 만들고 실제 변경을 보여준다.
- 초안, 질문, 창작적 가정, 채택 기록을 구별한다. 중요한 불확실성은 작품 본문에 사실처럼 섞지 않고 다음 판단으로 연결한다.
- 작업을 닫거나 프로세스가 끊겨도 저장된 문서와 미결 작업에서 이어간다.
- 이전 본문 복원은 새 revision이다. 이후 사용자 수정이나 새로운 원문 기준을 조용히 지우지 않는다.

## 변하면 안 되는 것

Candidate는 승인 결과가 아니다. current source/hash와 검토한 실제 내용에 채택을 결속한다. 외부 작성 프로그램의 성공은 후보 생산 성공이며 작품의 최종 승인이 아니다. `outcome_unknown`을 실패로 단정해 새 유료 호출을 시작하지 않는다.

스토리·서사·자산의 owner를 합치거나 외부 프로젝트의 의미 모델을 몰래 가져오지 않는다. producer가 계약을 소유하고 consumer copy는 registry에서 pin한다. 원문·문서·권리·기존 public contract를 사용자 동의 없이 정리 대상으로 취급하지 않는다.

현재 기능은 [SPEC](SPEC.md)·[Current](IMPLEMENTATION_STATUS.md), owner별 미완료 범위는 [PLAN](PLAN.md)을 따른다. 원문에서 판본까지의 다섯 작업 구간과 18개 세부 Target은 [정밀 작업 명세](STAGE_EXECUTION_SPEC.md)에 둔다. 이 Target은 현재 CLI의 단계·호출·승인 수를 선언하지 않는다. 개발 노트·보존표·새 매체 profile 등 설계 개념은 호출 가능한 API로 취급하지 않는다.
